# 一张 H20 跑出第一份 LoRA

适合第一次使用项目。完成[环境配置](00_环境配置.md)后，只需本地 Qwen3-8B 和一张 H20。脚本会生成 v2 记忆决策场景，采样训练数据，更新学生 LoRA，再用独立开发集比较训练前后的表现。这个例子全程在本机运行。

学生学的是何时跳过（`noop`）、回读原文（`recall`）、摘录多条记忆（`compact`），或把新反馈写入记忆（`write`）。例如，本轮收到一条编号更正时先写入，下轮被问到这个编号时再回读。[四种动作的完整例子](../plan/01_总体方案与架构.md)

## 1. 预览并启动

```bash
CUDA_VISIBLE_DEVICES=0 ./scripts/smoke_1h20.sh --plan runs/v2-smoke
CUDA_VISIBLE_DEVICES=0 ./scripts/smoke_1h20.sh --run  runs/v2-smoke
```

`--plan` 打印将要执行的命令，可以先看 Python 和模型路径。`--run` 才开始采样和训练。首次使用尚不存在的输出目录；想独立重跑时，把两行中的 `runs/v2-smoke` 换成新名字。

## 2. 查看结果

默认生成 128 个训练状态、64 个开发状态，每个状态采样 16 次，训练 1 个 epoch。成功后在 `runs/v2-smoke/` 查看以下文件。

| 文件 | 用途 |
|---|---|
| `train.jsonl`、`dev.jsonl` | 冻结的训练与开发数据，可以直接用于下一次离线实验 |
| `train/checkpoint-0001/adapter_model.safetensors` | 第一轮训练出的 LoRA 权重 |
| `train/checkpoint-0001/training_state.pt` | 优化器状态和训练进度，供续训使用 |
| `dev-score.json` | `reward_delta` 是相对未训练学生的平均奖励差，`success_delta_pp` 是成功率变化的百分点 |

开发集差值可以为负。要衡量这份权重对真实任务的影响，可以继续做原生 harness 的配对评测。使用下方链接中的示例时，先设置 `T="$SKILL_RSI_PYTHON"`，将 `runs/poker-offline` 换为本例的 `runs/v2-smoke`。做四臂评测还需先完成在线训练，并把 `--online-result` 指向实际生成的第二轮 `result.json`。[四臂评测用法](../README.md#启动学生服务并做四臂配对评测)
