# 贡献新的后训练算法

**一项算法，一个目录。** 假设你想试一种新方法，让学生更倾向于选择高分的记忆动作。你只需要在 `skill_rsi_rl/algorithms/my_method/` 实现训练和测试。项目根据文件名发现可用模式，安装与提交时都无需登记算法名。

## 1. 哪些文件可以改

| 范围 | 贡献者怎么用 |
|---|---|
| **可改** · 自己的 `skill_rsi_rl/algorithms/<算法名>/` | 放训练入口、样本筛选、损失、算法参数、测试及该算法的说明。实验输出另写到 `runs/<实验名>/`。 |
| **只读** · 同级其他算法、`algorithms/__main__.py`、`algorithms/api/` | 前者可作参考，后两者由框架维护者管理。加算法无需修改入口、注册表或打包配置。 |
| **只读** · 原训练器、数据协议与评测 | 包括 `train.py`、`online.py`、`rollout_batch.py`、`contracts.py`、`harnesses/`、服务与评测代码。沿用公共接口读取数据、保存权重。 |
| **只读** · 项目共享文件 | 包括 `EasyR1/`、`vendor/`、`configs/`、`scripts/`、`env/`、`tests/`、`pyproject.toml` 和 `sources.lock.json`。算法特有的默认值和可选依赖说明放在自己的目录。 |

例如给 DPO 加一个偏好强度参数，就在自己的 `offline.py` 里解析。在同一状态里构造优选、次选动作对，计算它们相对参考策略的得分差，也都属于该算法。若想增加第五种记忆动作，这会同时改变采集、执行和评测协议，应作为独立的框架变更讨论。

## 2. 从可运行的例子开始

`best_action_sft` 示范了另一种训练规则。同一状态下，如果 `noop / recall / compact` 得分分别是 4.3、9.9、3.4，它就把 `recall` 当作监督标签，最小化 `-log P(recall)`。每个状态只贡献一个样本。奖励同分并列第一，或缺少任一候选的分数，都会跳过该状态。它优先读取完整的 `option_scores`，也能从覆盖全部候选的 `samples` 还原评分。[样例实现](../skill_rsi_rl/algorithms/best_action_sft/offline.py)

进入项目根目录，激活训练环境，设置 `SKILL_RL_MODEL`。下面复用单卡首训产出的 train/dev replay。示例支持单进程 CPU 或单卡，默认训练一轮，每次选一个新输出目录。[环境配置](00_环境配置.md) · [生成第一份 replay](01_单卡首次训练.md)

```bash
python -m skill_rsi_rl.algorithms --list
DATA=runs/v2-smoke
OUT=runs/best-action-sft-01
CUDA_VISIBLE_DEVICES=0 python -m skill_rsi_rl.algorithms best_action_sft offline \
  --model "$SKILL_RL_MODEL" --replay "$DATA/train.jsonl" --output "$OUT" --device cuda
CUDA_VISIBLE_DEVICES=0 python -m skill_rsi_rl.dev_eval --model "$SKILL_RL_MODEL" \
  --device cuda:0 --adapter "$OUT/checkpoint-0001" --train-replay "$DATA/train.jsonl" \
  --replay "$DATA/dev.jsonl" --output "$OUT/dev-score.json"
```

`run.json` 记录算法名、版本、数据指纹、有效和跳过的状态数。`checkpoint-0001/` 是可重载的 LoRA。如果全部状态都被跳过，先查候选是否采全、最高分是否并列。样例提供离线模式，当前没有续训入口。原有 GRPO 命令仍可直接使用，也可经统一入口查看原参数。

```bash
python -m skill_rsi_rl.algorithms grpo offline --help
python -m skill_rsi_rl.algorithms grpo online --help
```

## 3. 加入自己的算法

下面在一个新的 `my_method/` 目录复制参考实现。修改其中的样本选择、损失和相应断言，即可独立开发。样例从包名写入实验身份，复制后的测试也会导入本目录的实现。

```bash
mkdir skill_rsi_rl/algorithms/my_method
cp skill_rsi_rl/algorithms/best_action_sft/{__init__,offline,test_offline}.py \
  skill_rsi_rl/algorithms/my_method/
python -m skill_rsi_rl.algorithms --list
python -m skill_rsi_rl.algorithms my_method offline --help
python -m unittest skill_rsi_rl.algorithms.my_method.test_offline
```

选一个与现有目录和 Python 模块均不重名的算法名。以小写英文字母开头，后续可用小写字母、数字或下划线。目录含 `__init__.py`，每种已实现的模式提供一个文件。

| 文件 | 约定 |
|---|---|
| `offline.py` | 提供无必选入参的 `main()`。自行解析命令行，从固定数据构造样本，执行更新。 |
| `online.py` | 同样提供 `main()`。由算法定义采样、更新和权重发布的轮次。只开发离线算法时省略这个文件。 |
| `test_*.py` | 测本算法的样本构造、损失、梯度和边界条件。可用相对导入 `from . import offline`。 |

例如运行 `python -m skill_rsi_rl.algorithms my_method offline --help` 时，`my_method.offline.main()` 收到的是 `--help`。训练时也是同样的规则，模式名之后的参数原样交给算法。选择未实现的模式时，入口会在加载模型或启动采集之前报错。

## 4. 复用框架的哪一层

| 需要什么 | 可以调用什么 |
|---|---|
| 读取训练数据 | `algorithms.api.read_training_replay(path)` 返回 `(manifest, groups, replay_sha256)`。它检查训练许可、train 划分、分片、行为策略身份和候选协议，保留算法自己决定哪些样本可学的空间。 |
| 核对评分与 token | `frozen_sample_scores(group)` 检查同一候选的冻结评分一致性。`validate_replay_tokens(...)` 检查当前 tokenizer 能复现当时的输入和候选。两者都在 `algorithms.api`。 |
| 加载模型与计算概率 | `load_lora_policy(model_path, device, lora_rank=...)` 返回可训练模型、tokenizer、填充 token ID。`option_logprobs(...)` 返回每个合法候选的对数概率。算法自行计算交叉熵、偏好损失等目标。[公共接口](../skill_rsi_rl/algorithms/api/__init__.py) |
| 对接现有开发集评测 | 用 `serve.checkpoint_identity` 获取基座指纹。用 `training_artifacts` 的 `lock_output`、`initialize_run`、`save_checkpoint` 输出标准 LoRA。把 `base_checkpoint_id`、`replay_sha256` 及算法身份写入 `run.json.settings`，评测器即可核验来源。[产物接口](../skill_rsi_rl/training_artifacts.py) |

**离线算法**自己决定怎样使用奖励。GRPO 需要组内回报差，SFT 需要监督标签，DPO 需要同一输入下的偏好对。项目的 `verify_replay` 和 `dev_eval --train-replay` 还会核验训练集是否含有效 GRPO 组。比如每个状态只采样一次，但保存了全体候选的评分，SFT 仍可从唯一最高分学习。这种数据可在评测时省略 `--train-replay`，报告中的 `scenario_disjoint_verified` 会是 `false`。需要额外数据格式的算法，把读取和转换代码放在自己的目录。

**在线算法**可以通过已有学生服务和 `skill_rsi_rl.harnesses.runner` 启动原生轨迹。冻结本轮权重，记录每条轨迹的策略 ID、动作回执和官方奖励。更新成功后发布新 ID，下一轮用新权重采样。在自己的 `online.py` 里定义轨迹筛选和优化器更新。原有 `rollout_batch.check_group` 会拒绝整组回报相同的轨迹，`update_policy` 使用 GRPO 损失。若算法还训练价值模型，把它保存在本算法的运行目录，另行导出标准的学生 LoRA 供原评测器使用。[原生轨迹入口](../skill_rsi_rl/harnesses/runner.py) · [原有在线轮次实现](../skill_rsi_rl/online.py)

## 5. 提交前怎样验证

1. **入口** · `--list` 列出自己的算法和模式，`<算法名> <模式> --help` 展示本算法的参数。
2. **学习信号** · 用一组手算得出答案的数据测标签或损失。至少做一次实际反传和更新，检查目标动作的概率、梯度或参数按预期变化。
3. **产物** · 新目录完成一次最小训练，重新加载 LoRA，核对基座、数据指纹和开发集结果。声明支持在线或续训的算法，还需验证下一轮加载上一次权重、重复运行能识别已提交的步骤。
4. **改动范围** · 在 Git 仓库中，将 `BASE` 设为目标分支。以下命令检查已提交的分支差异。自己的算法目录以外有改动时，命令列出路径并以非零状态退出。

```bash
BASE=origin/main
git diff --exit-code --name-status --no-renames "$BASE"...HEAD -- . \
  ':(exclude)skill_rsi_rl/algorithms/my_method/**'
```
