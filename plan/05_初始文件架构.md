# 05｜初始文件架构

2026-11-20 · 实施计划 · [总体方案](01_总体方案与架构.md) · [复用清单](03_代码复用与接入决策.md) · [实施与验收](04_实施阶段与扩展.md)

## 1. 项目根与交付边界

以下结构以 `skill_rl_train/` 本身为发行根。将整个源码目录复制、改名或解压后，在新位置重建虚拟环境，安装这里的项目包与固定的上游代码。首次合成训练从空输出目录开始；恢复训练时再带上对应的运行产物。

| 随项目交付 | 由运行机器提供 |
|---|---|
| 学生合同、合成场景生成器、replay 读写、训练/恢复、服务、评测、入口脚本和测试 fixture | 兼容的 Python、系统库、训练 GPU/驱动、基座权重与匹配 tokenizer |
| EasyR1 与官方 CL-Bench 的固定源码、许可证、必要任务定义及 schedule、版本和文件哈希 | 大型任务数据、镜像、已有 replay 或历史快照按所选实验提供。合成 v2 运行时生成 |
| DSH 插件与运行桥接、Codex/Claude 的 Query 包装器、示例配置和按端安装说明 | 运行该端所需的原生 CLI、网络/本地服务、账号凭据。单卡离线训练只需要训练环境 |

## 2. 发行目录与模块职责

```text
skill_rl_train/
├── README.md                         全新机器的安装、单卡首训、三端实验入口
├── pyproject.toml                    一个可安装包 skill_rsi_rl，核心合同可无 torch 导入
├── env/                              训练依赖及 H20 约束；benchmark 的 uv.lock 位于 vendor 内
├── sources.lock.json                 第三方提交、授权声明、文件清单与内容哈希
├── EasyR1/                           已有固定快照，随项目分发其实际源码和 LICENSE
├── vendor/continual-learning-bench/  固定官方源码、打包文件、配置、任务资源清单与许可证
├── skill_rsi_rl/
│   ├── contracts.py                  共享的状态、候选、token 与动作合同
│   ├── collect.py / scenarios*.py    生成 v2 数据，或从已评分的同态候选采样
│   ├── replay_io.py / replay_spec.py / verify_replay.py
│   ├── train.py / easyr1_backend.py / replay_objective.py
│   ├── preflight.py / training_artifacts.py / tracking.py
│   ├── serve.py / policy_configs.py / dev_eval.py / compare.py
│   ├── fresh_branches.py / branch_score.py   三端从共同初态评分，DSH 可另从历史分支恢复
│   ├── online.py / rollout_batch.py          同步采样、组批、更新与恢复
│   ├── evaluate.py / sources.py              配对评测及发行源码校验
│   └── harnesses/
│       ├── runner.py                 三端共用的原生 rollout 入口，含 Codex/Claude Query 包装器
│       ├── dsh_system.py / memory_policy.py  DSH 系统、共用策略客户端与回执
│       └── plugins/clbench-submit/   DSH 原生提交插件；同包另含历史分支恢复及配置
├── configs/                          v2 默认参数、Poker 训练/留出拆分和三端配置
├── scripts/                          setup.sh、smoke_1h20.sh、eval_dsh.sh 等本地入口
├── tests/                            已迁入的 replay、训练、分支与评测回归用例
└── plan/                             设计文档及图
```

同一行列出的模块分别为同目录下的文件。旧项目是一次性迁移来源。离线及在线入口统一使用 `skill_rsi_rl` 包名，合同、候选打分和损失各维护一份。

| 阶段 | 源码与资源归属 | 独立运行的检查点 |
|---|---|---|
| P0/P1 | 从历史训练代码迁入离线模块及其传递依赖、测试、单卡脚本。安装脚本从当前目录安装项目包和 EasyR1 | 从隔离目录生成分组 replay，在 H20 上训练、重载 LoRA 并产出 dev 报告 |
| P1/P2 | 官方 benchmark 源码放在 vendor 下。将 DSH 桥接、`clbench-submit` 插件、runner 用到的恢复模块与配置纳入项目。策略服务扩展采样，在线训练器读取落盘轨迹 | DSH 在独立的 benchmark 进程运行，使用项目内的合约和插件，以文件和回环 HTTP 连接训练进程 |
| P3/P4 | Codex/Claude 包装器委托随项目交付的官方系统，配对计算复用本地 `compare.py` | 在同一份发行目录上逐端执行 CLI smoke、在线两轮更新和留出评测 |

默认输出使用项目内 `runs/`，可显式指定输出目录。基座、数据、归档及历史数据的授权记录都是可选路径或必需实验输入，按模式配置。代码与插件由本地包和发行清单定位。原生插件、数据模板等文件必须随安装可用。

## 3. 一次新实验的产物

```text
runs/
├── p1-v2/offline/                    train.jsonl、dev.jsonl、train/checkpoint-0001/、dev-score.json
├── poker-online/
│   ├── manifest.json                 实验配置、训练源码、benchmark 与初始策略身份
│   └── round-0001/
│       ├── group-0001/replica-0000/  rollout.json 与同目录的官方 trace.json.gz；失败有错误记录
│       ├── batch.json                封存的有效组、分母、拒收原因、父策略与输入摘要
│       ├── checkpoint/               更新后的 LoRA、优化器与恢复状态
│       └── result.json               已发布的 policy ID、更新次数及诊断
└── evaluations/<tag>-<profile>/
    ├── manifest.json                 固定的配对条件、各臂权重、配置及源码身份
    └── paired-report.json            官方分数、成功率、覆盖、配对差与开销
```

离线实验只创建 `offline/`，在线实验只创建实际完成或尝试的轮。大型权重和原生会话用可解析的路径和哈希引用。发布时先落 checkpoint 再原子提交完成记录。重启验证父权重、批次指纹、优化器步数和已发布子权重，损坏或缺失的轮可在独立 attempt 中重新执行。已完成产物永远能指回当时的输入。

## 4. 交接时从哪里看

1. 判断能否训练，读 `batch.json` 或旧 replay 校验报告，确认来源、策略身份、分组和可用分母。
2. 判断权重是否实际生效，对齐 checkpoint 身份、服务健康响应、Query 回执与评分产物的 run/attempt。
3. 判断训练是否带来收益，读该 harness 的 `paired-report.json`，核对完整配对数与区间。原生执行失败、无可学习的决策、得分无提升各自有独立的诊断入口。
