# 02｜数据协议与验收

2026-11-20 · 实施计划 · [总体方案](01_总体方案与架构.md) · [验收顺序](04_实施阶段与扩展.md)

**共享“学生看见什么、选了什么、实际发生什么”的记录。** 离线按同一决策状态分组，在线按同一初始条件下的完整序列分组。两种组的含义不同，分别校验后才送入同一个损失函数。

## 1. 数据单位与来源

| 单位 | 最小内容 | 来源与检查 |
|---|---|---|
| 运行清单 | harness、执行模型和配置、学生基座/adapter/tokenizer/候选规则指纹、任务/schedule/seed、用途与 split、数据或轮次 ID | 权重身份取自服务和训练端。一次环境执行有唯一 attempt，重复导入同一 attempt 幂等 |
| 可见状态 | query、此前已公开的 feedback、**动作前**学生 memory、有序 options、渲染后的 prompt IDs 和标签 token IDs | 复用现有 bound/render 函数，重算输入哈希。scorer 私有标签、未来反馈出现在输入时拒收 |
| 学生决策 | Query ID、policy ID、抽样设置和 seed、完整候选 logp、抽中索引、实际动作与执行状态、记忆前后哈希 | 采样器写分布，宿主确认应用。校验 exp(logp) 之和约为 1、候选有限且所选索引匹配。服务超时的 fallback 单列 |
| 环境结果 | run/attempt、实例 ID 与顺序、官方 reward 和原生 success、评分窗口、终态、原始产物引用 | 按身份连接官方 outcomes。保留合法零奖励，缺失结果记录原因，独立统计失败与覆盖 |

基座、tokenizer、chat template 和候选支持集进入数据指纹。每个候选标签须映射为一个独立的非特殊 token。在线整段留存学生实际决策串，压缩或重写后以下一次真实输入为准，大型原生日志只保留引用。合同由项目内的 `skill_rsi_rl/contracts.py` 提供，历史实现仅作为迁移时的对照。

## 2. Off-policy 合同与目标

沿用现有 JSONL。manifest 之后每行是一个 `state_id` 的冻结组，保留 `messages / prompt_token_ids / options / option_token_ids / behavior_logprobs / samples`。每个 sample 有 `option_index / reward / native_success`。同一个选项重复被抽中时引用该选项的同一份冻结评分。离线组最少两次抽样，并有 reward 差异才贡献策略梯度。迁入后的采集与校验入口分别为 `python -m skill_rsi_rl.collect` 和 `python -m skill_rsi_rl.verify_replay`。

| 来源 | 怎样使用 | 结论边界 |
|---|---|---|
| 独立合成开发场景 | 先恢复远程 v2 离线基线，生成共享 checkpoint 给三端做迁移评测 | 表中 reward 来源标作 synthetic，单独报告 CL-Bench 评测 |
| 来自 CL-Bench 的冻结状态 | 从训练划分取同一环境、执行器会话和记忆边界，为各候选独立跑相同的后续窗口，再用冻结学生按实际 μ 抽样 | DSH 先用已有 Poker 分支评分。Codex/Claude 新增同态验证后再建各自的 spec，记录后续控制策略、原始结果和每个候选的汇总法 |
| 普通原生聊天记录或既有评测 | 用于查状态、构造可见输入或配对评测。重评分要核对原数据用途、边界与拆分 | 原生工具日志中的动作没有学生行为分布。单次历史结局不能给未执行的候选打分 |

离线损失沿用旧后端。每个状态按已抽样奖励求组内优势，用 `πθ(a|s) / μ(a|s)` 做 clipped surrogate，加对冻结参考策略的候选分布 KL，按状态等权聚合。沿用离线实现的总体标准差（pstdev）。μ 是实际采样分布，包含当时的温度和 uniform mix。报告有效组数、剔除原因、clip fraction、有效样本量比例和 KL。该目标优化已记录状态上的候选选择，最终任务收益通过独立原生运行衡量。训练端和 EasyR1 适配均随项目交付。[代码归属](03_代码复用与接入决策.md)

## 3. On-policy 合同与目标

一次在线组固定 `harness × 训练任务 × schedule/实例顺序 × 环境 seed × 执行器配置 × 初态 × policy_id`。首版从官方序列起点启动 G 条独立会话，建议 G=4，至少 2 条。每条会话单独使用 workspace、记忆和学生采样随机流，按官方规则跨实例续接。可从新初态重建的三个 harness 都能用这个做法。

1. 轮首冻结 πₖ，采样服务在候选集上按温度 1、uniform mix 0 抽样。每次决策记录所选标签在 πₖ 下的 logp。只有一个合法候选时照常执行，在损失中掩去该步。贪心服务继续用于配对评测。
2. 对固定长度完整序列，取预先约定的官方实例 reward 均值为 `Rᵢ`。同组 rollout 按 `(Rᵢ − mean(R)) / (std(R) + ε)` 得到整条序列的优势。线上沿用固定版 EasyR1 的组内样本标准差。所有可训练的学生决策承接该优势，从而覆盖“先写入、后回读”的延迟收益。不同任务、不同初态、不同 harness 各自成组。
3. 从每步原始学生输入重算当前策略的候选 logp。仅学生实际抽中且已应用的动作进入 loss。用 `exp(logπθ − logπₖ)`、组优势和决策 mask 调用 EasyR1 clipped loss，按序列平均有效决策再按序列等权。总损失另加 β 乘以当前候选分布到冻结参考分布的完整 KL，使用相同的掩码与序列归约，参考分布停止梯度。执行器文本、工具返回、环境反馈只作证据。首个优化步前校验新旧 logp 数值一致，记录容差、最大误差与 dtype。
4. 先封存有效批次，再做一个 optimizer step 并冻结新 adapter。下一轮新采。保持优化器状态连续，固定 KL 参考为同一初始基座。轮内若有服务身份错、fallback、缺评分、意外截断或漏回执，保存错误并重采整组，组内全同奖，或任一序列全是强制动作时，整组计入跳过数。设置采样组数/预算上限，耗尽仍无有效组则报告无更新。

**为什么需要新的批次转换。** 离线行规定同一选项对应固定评分，在线两个 rollout 即便首步抽到同一选项，后续决策和收益也可能不同。在线记录以 `group_id / rollout_id / round_id` 加有序 decisions、官方 outcomes 存储。转换时按 rollout 建优势，按决策生成训练输入，保留 rollout 索引用于归约。离线的 `prepare_groups` 与 replay 校验继续解释旧文件。

## 4. 入库、拆分和恢复验收

| 检查 | 通过条件 | 负例 |
|---|---|---|
| 划分 | 先按场景/环境资源与整条实例序列划分 train、dev、官方留出，再派生前缀。检查 state ID、scenario ID、可见输入哈希与实际实例/语料交集 | 同一历史分支的兄弟样本跨 split，Poker quick 与正式集共享 seed 却标为独立留出 |
| 同态与支持集 | 离线每个候选对应同源状态及同一评分窗口，在线同组从同一初态开始、之后允许各走各的状态 | 用相同问题文本代替恢复会话和环境，或把不同动作支持集拼成一个离线组 |
| 动作生效 | 每 Query 一次，订正复用回执，`write → recall → 实际 memo` 可串联，reset 后恢复规定初态 | 只收到服务响应就记作已应用，或让不同 replica 共享文件 |
| 策略与计分 | 在线各轨迹 policy ID 均等于轮首权重，训练输入可重算抽样 logp，拥有完整实例与可追溯 reward 来源 | 混入旧轮、以贪心输出伪造采样、把失败计成 reward 0 |
| 幂等与恢复 | 采样封存、更新、发布各有完成记录，重启时按批次哈希和父 checkpoint 接续。已发布轮跳过更新，半成品用最近完整状态重做 | 相同批次更新两次，或更新完成后仍用旧服务收下一轮 |

既有 `dsh-full-m4-v1` 的默认用途是评测。本地已有仅覆盖指定 manifest 与 Poker 新评分分支的训练授权记录，使用时匹配其范围并从留出中移走重叠实例。新实验优先建立独立训练 schedule 或 corpus。只有选用该历史数据时，才由实验配置显式传入归档、授权记录并检验 manifest 匹配。

## 5. 搬迁后定位数据

- 首次训练默认由项目内 v2 场景生成器和指定的本地学生权重产生真实 train/dev replay。也可传入已有的合格 replay，跳过采集，CPU fixture 用于验证数据合同。
- 官方任务选择、训练/留出 schedule 及资源清单随源码交付。按任务读取外部数据时，配置记录逻辑资源名、版本、哈希和本机数据根。归档、重放与评测根据标识和内容摘要匹配数据。
- 新 manifest 中，运行产物使用相对运行目录的引用，源码文件使用相对项目根的引用，外部资源通过配置重新绑定。复制项目或搬迁同一批次后，必须仍能加载 checkpoint、校验 replay、定位报告，不依赖原服务器绝对路径。
- 搬迁验收时保留一组三项身份：原始 replay 的 SHA-256、基座与 tokenizer 的内容身份、所选 LoRA 的策略身份。复制后从新路径读取并逐项比对，在相同超参数下接续一个 epoch。新报告能定位其相对轨迹，且源目录未挂载，即满足数据侧的独立性要求。
