**无 Git 元数据的源码包也要通过预检。** 在迁入时从已核定的 EasyR1 提交 `a73346d028ba0335aa42da104972c86e6cd0fe69`、官方 CL-Bench 提交 `5f8c50eb1e84b2eda2ef4faff757dfc812a0ea26` 生成 `sources.lock.json`，记录实际分发文件的相对路径与 SHA-256，并保留原始许可证与必要声明。对宿主工作树的本地修改另存来源版本和内容摘要。训练后端、benchmark runner 和历史分支恢复统一用这份发布清单验证来源，拒收缺文件、错哈希或额外覆盖的源码。历史归档继续核对其记录的任务资源和提交。这样，普通目录复制和去掉 `.git` 的源码归档都能重复验证。

**兼容旧 checkpoint 身份。** 历史服务把 `contracts.py` 的完整字节计入策略 ID。迁移时用旧样本验证同一权重、tokenizer 和候选规则的实际身份。若为移除机器路径而改变合同指纹，记录新身份及其与旧 checkpoint 的来源关系，重新生成服务配置，历史报告继续引用原身份。

## 2. 为什么复用到 EasyR1 的这一层

原生 `python -m verl.trainer.main` 走 Ray trainer → vLLM 生成响应 → reward → actor 更新。这里要优化的动作，是原生 Query 过程中学生从动态候选里抽中的一个标签，下游奖励可能到后续实例才出现。只改 reward 回调无法取得当时的候选分布、记忆回执和下游状态。旧 DSH 已把这些问题拆开，首版沿用它的训练边界。[原生 trainer](../EasyR1/verl/trainer/ray_trainer.py) · [reward 回调](../EasyR1/verl/workers/reward/function.py)

离线保留经过验证的有限动作后端。在线使用同一 `option_logprobs` 得到每步有限候选的分布，同时记录 chosen logp。把每条轨迹的回报放在最后一个有效学生动作上，向每条序列传入同一实验组共有的 `group_id`（Python 标量列表）和 decision mask，调用 `compute_grpo_outcome_advantage`，把优势广播给该序列的有效学生决策。再用 `compute_policy_loss` 计算按序列平均的损失。对照小张量手算一次，特别核对 padding、变长序列以及每条轨迹的权重。固定行为 μ、轮首 πₖ 和 KL 参考模型各有独立身份。

## 3. 三个 harness 的适配边界

| Harness | 调用点 | 第一条能证实接入的证据 | 特有的检查 |
|---|---|---|---|
| DeepSeek Harness | 旧实现的 `DSHSystem.respond` 已在首个 `session/prompt` 前决定记忆动作 | 同一 Query 对应策略回执、实际 memo/记忆哈希、成功的 `clbench_submit` 及官方 outcome | 只启用 DSH 已有钩子，统一采样模式，现有 fallback 评测语义继续记录 |
| Codex | 官方 `CodexSystem.respond` 前创建保留原 schema、实例身份和公开反馈的 Query 副本，按动作附 memo | 学生回执 → 实际 CLI 起始/续会话输入 → 官方 schema 合格的 action → scorer | `codex exec resume`、文件记忆与 cumulative usage 使用原生实现，按 rollout 隔离可写目录 |
| Claude Code | 同一包装器委托 `ClaudeCodeSystem.respond`，由原生系统管理工具循环与 repair | 学生回执 → 实际原生 prompt → stream-json/session → 官方 outcome | 保留 resume、原生 memory、cache usage。工具调用和 repair 均沿用 Query 的第一次决策 |

包装器只把学生 memo 放到执行器实际可见的输入。学生仅消费宿主本来允许看到的反馈文本。`observe` 与下一 Query 携带同一反馈时按实例/步标识消费一次。保留官方原始 Query、实际发送版本和回执，便于回查。新 run、baseline reset 和并行 replica 的学生记忆归属必须与官方运行边界一致。首版沿用 DSH 的回环 HTTP，由宿主进程访问学生服务。CLI 容器只接收已准备好的输入。

## 4. 有选择地借用 CLM

| 来源 | 在本项目中的用途 |
|---|---|
| CLM 的 ATIF-CTX | 上下文被改写时保存新 segment 的真实可见输入。学生的短输入和原生长轨迹通过 Query ID 关联，已有原生记录优先用引用 |
| CLM 的双通道优势 | 借用“优势只到对应动作”的掩码思想。首版只用任务回报。后续若能可靠测量成本，可单独做效率项消融，分别报告 reward 与成本 |

宿主进程只加载本项目的轻量合同并调用策略 HTTP。训练进程加载模型、优化器和项目内 EasyR1。旧项目的相邻目录查找、全局 `PYTHONPATH` 注入、指向旧目录的软链接和 worktree 均在迁入时移除。DSH 插件按安装资源定位，官方数据路径由任务配置传入，凭据由运行环境注入。
