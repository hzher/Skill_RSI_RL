## 2. 实施顺序与退出条件

| 阶段 | 从哪里开始，交付什么 | 怎样算完成 |
|---|---|---|
| P0 建立可搬迁项目 | 迁入离线训练包及传递依赖、v2 场景、已有回归和脚本。提供根目录安装入口，固定 EasyR1 源码和 H20 依赖，删除旧工程的路径推断 | 仅向空容器复制本项目（去掉 Git 元数据），验证安装、导入来源、CPU fixture 及拆分。篡改固定源码时预检能报出具体文件 |
| P1 独立单卡训练与 DSH 离线 | 先用本项目单卡入口完成 v2 真实采集 → replay 校验 → LoRA → dev。随后迁入官方 benchmark 和 DSH 全部必要资源，完成 Poker quick 三臂和训练划分的候选分支评分 | 单卡在没有任何 harness 凭据时产出可重载的 adapter、恢复状态和 dev 报告。启用 DSH 后，合成与 CL-Bench 来源分别有有效组、有限 loss 和可追溯的官方回执 |
| P2 DSH 在线 | 冻结一个学生版本，从 Poker 训练划分的序列起点跑独立 replicas，收齐官方 outcomes，按 [02](02_数据协议与验收.md) 做一个更新，重复一轮 | 两个有效批次、两次参数更新，第二轮服务身份等于第一轮产出。从原始输入重算学生 logp，更新前 ratio≈1，更新后确认学生参数有变化。拒绝过期轨迹，重试同一批次只提交一次 |
| P3 Codex、Claude Code | 接同一 Query 包装器。每端先验原生/空干预，再验真实写入及后续回读。各自运行 P1 的冻结策略评测和 P2 的在线闭环 | 每端给出独立产物。CL-Bench 来源的离线实验另核同前缀分支，可从新 workspace 重建共同前缀并验证环境/会话/记忆。无法核对的前缀保留拒收原因 |
| P4 小模型对照 | 以同一初始基座分别做离线和在线训练，冻结选模规则与预算，在未用于训练或选择的官方序列上配对 | 各端填满下表的来源、状态和路径。按任务给出配对差值、覆盖及成本，有足够完整配对才报告收益结论 |

P1/P2 先维持单机、同步采样和单卡更新。显存或用时需要时，沿用旧 `torchrun` 配置扩卡。更小基座可在这条链通过后试同族 Qwen3-4B，先检查权重、模板、候选标签 token，重新采集 replay 并为该基座建立未训练对照。EasyR1 的 [4B LoRA 示例](../EasyR1/examples/qwen3_4b_math_grpo_lora.sh) 可参考显存配置。

## 3. 六个实验格如何填

| Harness | Off-policy 实验 | On-policy 实验 |
|---|---|---|
| DSH | 复现合成训练→官方评测，另做开发 Poker 同态分支的冻结 replay→更新→留出评测 | 当前学生采训练划分的 Poker，至少两轮更新，再固定学生评估 |
| Codex | 先以共享离线权重做迁移，再用本端可验证的同态分支建固定 replay，训练一个本端版本 | 同配置 Codex 独立会话从相同起点采样，按组更新 |
| Claude Code | 沿用同一数据规范与训练命令，另收本端同态分支，分别登记迁移与本端离线结果 | 同配置 Claude Code 独立会话从相同起点采样，按组更新 |

每格保存数据来源、训练初始/最终 checkpoint、评测配置和报告。共享权重迁移可先验收“能部署”，本端 CL-Bench 离线训练格须有本端评分的 replay 和新训练产物。若无法克隆中途会话，可直接从训练序列的第一个 Query 做候选对照。各分支从相同种子、空原生 workspace 和同一份预置学生记忆启动。记忆只取训练划分已公开的示例或反馈，并记录来源。先验至少两个合法候选，再冻结相同的后续规则与评分窗口。把此来源标为“预置记忆训练”，正式留出从官方规定初态启动。全同奖组报告为零信号，中途分支能力另列状态。

## 4. 独立项目验收命令（实施后执行）

实验命令从交付的 `skill_rl_train/` 根目录运行；安装和首次训练的完整示例见[项目 README](../README.md)。验收机只接收一份去掉 `.git`、已有虚拟环境和历史 `runs/` 的项目副本，所在挂载点仅含这个项目。清除环境中原有的 `PYTHONPATH`，在全新容器或新机器安装，确保原工作区与原环境均不可见。

**P0 · 安装与 CPU 数据回归。** 从开发机只传项目源码到训练机上的空目录。可以在开发机从 `skill_rl_train/` 根运行以下归档命令；在训练机的空目录解包后，从解包目录执行本节后续命令。模型通过 `MODEL_DIR` 单独挂载。归档排除已有环境、运行数据及本地凭据，使首次安装实际覆盖可搬迁边界。

```bash
tar --exclude=.git --exclude=__pycache__ --exclude=.DS_Store --exclude=.env \
    -czf /tmp/skill_rl_train-src.tgz README.md pyproject.toml sources.lock.json LICENSE.dsh \
    env configs scripts skill_rsi_rl tests plan EasyR1 vendor
# 将归档复制到训练机后，在目标空目录执行
tar -xzf /tmp/skill_rl_train-src.tgz
```

`setup.sh train` 使用选定的训练 Python 创建项目本地 `.venv-train`，按 H20 约束安装训练依赖，并从本项目目录安装 EasyR1 和 `skill_rsi_rl`。预检报告实际导入的源码路径和指纹。仅做 CPU 合同测试时，可用 Python 3.10+ 从项目根执行下方 unittest 和 fixture 命令，无需加载 GPU 后端。

```bash
unset PYTHONPATH
./scripts/setup.sh train
source .venv-train/bin/activate
python -B -m unittest discover -s tests -p 'test_replay*.py'
work=$(mktemp -d)
python -B -m skill_rsi_rl.collect sample --fixture --scenario-suite v2 --split train --seed 17 --states 16 --samples-per-state 8 --output "$work/train.jsonl"
python -B -m skill_rsi_rl.collect sample --fixture --scenario-suite v2 --split dev --seed 221 --states 16 --samples-per-state 8 --output "$work/dev.jsonl"
python -B -m skill_rsi_rl.verify_replay --train "$work/train.jsonl" --dev "$work/dev.jsonl"
```

**P1 · 真实单卡训练。** 在兼容 H20 的训练环境中，将 `MODEL_DIR` 指向含基座权重和 tokenizer 的目录，用新的输出路径执行。首次运行只需要项目源码、训练依赖和模型。命令负责生成 train/dev 数据、校验、做一次真实 LoRA 训练并加载权重做 dev 评估。

```bash
SKILL_RSI_MODEL="${MODEL_DIR:?set MODEL_DIR to a local Qwen3-8B directory}" \
  SKILL_RSI_SCENARIO_SUITE=v2 ./scripts/smoke_1h20.sh --run runs/p1-v2/offline
test -s runs/p1-v2/offline/train/checkpoint-0001/adapter_model.safetensors
test -s runs/p1-v2/offline/train/checkpoint-0001/training_state.pt
test -s runs/p1-v2/offline/dev-score.json
```

验收时从报告核对有效组、有限 loss、非零参数更新、输入 replay 指纹和 dev 所用权重身份。在同一份 replay 与配置上，从完整 checkpoint 恢复一次。将项目与该运行目录搬到另一绝对路径后，重新绑定模型目录并复核 adapter 身份和报告。

**P1–P3 · 三端 CL-Bench。** Codex/Claude 运行 `setup.sh bench`；DSH 运行 `setup.sh dsh`，会额外安装固定版 Node 和 DSH CLI。这些入口用 Python 3.13+ 创建 `.venv-bench`，从项目内 `vendor/continual-learning-bench/` 安装对应任务依赖（Poker 使用 `[poker]`）与项目内宿主包。GPU 进程仍使用训练环境。DSH 需要可用的原生 CLI、插件和服务凭据，Codex/Claude 按官方实现准备 Docker、固定版 CLI 与认证。任务数据按所选 profile 准备。离线单卡验收独立完成后再执行此阶段。

```bash
./scripts/setup.sh dsh
.venv-train/bin/python -m skill_rsi_rl.policy_configs --model "$MODEL_DIR" --report runs/p1-v2/offline/dev-score.json \
  --adapter runs/p1-v2/offline/train/checkpoint-0001 --output runs/p1-v2/policies
```

按 `policy_configs` 输出分别启动 base/trained 本地服务（现有默认配置使用两张卡），待两端健康检查返回对应的 checkpoint 后执行 DSH 三臂评测。在线入口由训练环境启动，按配置使用本项目的 benchmark 解释器运行原生宿主。切换 Codex 或 Claude Code 时只替换宿主配置。

```bash
./scripts/eval_dsh.sh --run --tag p1-dsh-quick --profile quick --task exploitable_poker \
  --base-policy runs/p1-v2/policies/base.json --trained-policy runs/p1-v2/policies/trained.json
.venv-train/bin/python -m skill_rsi_rl.online --config configs/poker-train.json --model "$MODEL_DIR" --rounds 2
```

从干净副本逐端验证插件加载、回执、官方评分和序列隔离。两轮在线验收要求每轮各有一次持久化更新、完整的 checkpoint 父子关系、数据哈希、覆盖与 loss 日志。若使用历史 Poker 分支，从配置显式传入归档和对应授权记录，在本项目的恢复与评分入口核对边界。合成首训始终可从空 `runs/` 启动。

## 5. 读实验结果

在每一端固定执行模型、原生工具/记忆设置、预算、评分器、初始状态和实例顺序。同一留出序列分别跑 native / base / offline / online，后三臂采用相同的贪心推理。native 是不挂学生的原生执行。训练方法对照固定同一个初始 checkpoint，单列生成/重评分消耗的环境交互、GPU 时长和可得的 token/费用。已有 replay 的采集成本也要计入。若另做 offline → online 热启动，单列为续训实验。

按完整 rollout 配对，报告任务原量纲 reward、native success、差值和配对区间，同时列出预期/完成/缺失序列、策略调用/fallback/实际注入次数。主要比较提前固定为 offline−base、online−base 和 online−offline，并保留相对 native 的差。Poker quick 每臂 1 条 × 5 手牌只验链路。正式收益按任务和完整序列给区间，样本量不足标为探索性。已有 DSH 报告沿用其原统计口径。跨 harness 表明各自执行模型与工具配置后，分别报告结果。
